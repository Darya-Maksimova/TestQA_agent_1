## 2. Этап 1 — Анализ требований (Skill: requirement-review)

**Scope:** управление товарами в корзине и оформление заказа авторизованным пользователем.

### Функциональные требования (из текста страницы)
- **Фича 1 — Добавление товара в корзину**
  - Сценарий 1.1: добавление доступного товара → товар в корзине, счётчик +1, тост «Товар добавлен».
  - Сценарий 1.2: товар «Нет в наличии» → кнопка «В корзину» задизейблена, текст «Сообщить о поступлении».
- **Фича 2 — Просмотр и редактирование корзины**
  - Сценарий 2.1: изменение количества «+» → количество 1→2, автоматический пересчёт итоговой суммы.
  - Сценарий 2.2: удаление товара → товар исчезает, общая сумма уменьшается.
- **Фича 3 — Оформление заказа (Checkout)**
  - Сценарий 3.1: успешное оформление (авторизованный) → создаётся заказ, страница «Спасибо за заказ», статус в ЛК «В обработке».
  - Сценарий 3.2: оформление без авторизации → модальное окно авторизации/регистрации.

### Бизнес-правила / ограничения
- Оформление заказа доступно только авторизованному пользователю (Сценарий 3.2).
- Покупка недоступна для товара без наличия (Сценарий 1.2).
- Итоговая сумма пересчитывается автоматически (Сценарии 2.1, 2.2).
- Для оформления обязательны: наличие товаров, выбор способа доставки и оплаты (предусловие 3.1).

### Пробелы / неоднозначности (зафиксированы, НЕ выдаются за требования)
- Не описан минимальный/максимальный предел количества (поведение «−», ввод 0, отрицательные значения).
- Не описано поведение счётчика при удалении всех товаров и при повторном добавлении одного и того же товара.
- Не указаны обязательные поля и валидация данных на шаге оформления (адрес, телефон и т.п.).
- Не описано поведение при недоступности сервиса оплаты / ошибках сервера.
